# 2CH_485HUB-V1.0 智能RS485集线器

## 📋 项目概述

**2CH_485HUB-V1.0** 是一个基于 **ESP32-S3** 芯片的企业级智能RS485集线器项目，专为工业自动化和物联网应用设计。该系统支持多种工作模式、智能协议处理、Web配置界面和OTA远程升级，是现代工业通信的理想解决方案。

### 🎯 核心特性

- **🔧 多工作模式**: 支持4种不同的工作模式，适应各种应用场景
- **🚀 高性能通信**: 支持高达115200bps的数据传输速率
- **🌐 智能网络管理**: WiFi STA/AP模式，Web配置界面
- **🔄 实时监控**: WebSocket实时数据流监控
- **📡 OTA升级**: 支持远程固件升级
- **🛡️ 安全控制**: 地址过滤、访问控制、AP超时管理
- **💾 配置持久化**: NVS存储，断电保持配置

## 🚦 启动/任务流程
- 上电 → Bootloader → `app_main` (`main/sx_main.c`)：初始化日志/时钟/引脚 → 打开 NVS → 读取工作模式/串口/网络配置 → 启动 WiFi、HTTPD/WebSocket、DNS 等基础服务 → 根据工作模式启动对应任务。
- 任务栈统一通过 `create_app_task_psram`（`sx_utils.c`）放到 PSRAM；系统内置任务保持默认内存。核心任务：
  - `rx_task_uart0/1/2`：串口接收常驻。CH1 不设亲和，CH2 固定 core0，CH3 固定 core1，避免长帧互抢。
  - 工作模式任务：透明/队列管理、Modbus 缓存轮询、自动采集轮询与虚拟从机应答等。
  - Web/系统：`httpd`、`ws_send_task`、资源监控 (`print_system_resource_usage`) 等。

## 💾 NVS 配置体系（主要键）
- 工作模式：`w_mode`（`/mode_set` 写，`/mode_info` 读）。
- 串口参数：`ch{1,2,3}_baud/data/par/stop/frame_time/frame_len/timeout` 等，由 `sx_async_uart` 启动时读取。
- Modbus 手动缓存：`m_count` + `m{idx}_en/rs/fc/ra/rn/...`；地址过滤/映射各自独立键。
- 自动采集：前缀 `ac2_/ac3_`，键 `*_maddr/count/itemN_{en/rs/fc/ra/mra/rn/int/to/baud/db/par/sb}`；`/auto_collect_set` 保存，`sx_auto_collect_init` 读取。
- 其他：网络、设备名、时间同步、OTA 标志等均在 `storage` 命名空间。

## 🧭 工作模式概览与策略
- **transparent_queue**（透传排队）：CH1/CH2 主站 → 队列状态机 → CH3 从站；IDLE 直接发，WAITING 队列调度，记录源通道路由响应；可叠加地址过滤/虚拟映射。
- **modbus_queue**（Modbus 协议排队）：在透传队列基础上做 Modbus 协议校验/路由，队列策略相同。
- **modbus_cache**：
  - 手动缓存：轮询真实从机，构建映射表，读请求逐寄存器拼装，可跨多条映射；写支持写后验证，失败计数/GC 清理。
  - 自动智能缓存开关：自动生成条目，逻辑同手动但条目来源不同。
- **master_slave**：CH1 主、CH2/CH3 从，按主从转发策略处理。
- **auto_collect**：CH2/CH3 各自轮询并缓存；CH1 作为虚拟从机应答，按手动缓存式逐寄存器拼装，单通道单虚拟从机，最多 60 条目/通道。

### 📥/📤 各模式读写处理速览
- **transparent_queue / modbus_queue**：读写均由 CH1/CH2 进入队列，转发至 CH3；响应按记录的源通道路由回去；`modbus_queue` 额外做功能码/CRC校验及过滤/映射。
- **modbus_cache（手动）**：后台轮询真实从机填充缓存；读请求在 CH1（或串口配置的接口）逐寄存器拼装，可跨多条映射；写请求暂停轮询→下发写命令→读回验证→更新缓存→恢复轮询。
- **modbus_cache（自动智能）**：同手动缓存，但条目由自动发现/生成；读写流程一致。
- **auto_collect**：CH2/CH3 轮询采集；CH1 作为虚拟从机提供只读访问，逐寄存器拼装，不支持写；单虚拟从机地址、可配置映射起始地址和寄存器数量。
- **master_slave**：CH1 请求转发到 CH2/CH3 从站，响应回 CH1；不做缓存。

## 🧠 内存与 PSRAM
- 业务任务栈用 PSRAM（`create_app_task_psram`），数据缓冲视模式在堆/PSRAM 分配；大配置时关注 PSRAM 占用。
- 资源监控：`print_system_resource_usage` 定期打印内部 RAM/PSRAM、任务 CPU/栈余量。

## 🔌 UART/RS485 与 Async UART
- `sx_async_uart` 统一管理三路 UART：接收任务常驻，发送支持临时串口配置（按条目动态波特率/校验位等），并提供 TX/RX LED 指示。
- 通道角色：CH1 为上位机接口；CH2/CH3 作为主站轮询或从站，取决于工作模式。自动采集中轮询在 CH2/CH3，虚拟从机应答在 CH1。
- 串口参数快速切换：提供临时配置发送后自动恢复的能力，配合工作模式的轮询/转发。

## ⚙️ 工作模式详解

### 1. 🔄 智能排队透传模式 (Transparent Queue Mode)

**全新重写的高性能排队系统**，基于零拷贝架构和智能状态机设计。

#### 🎯 核心架构
```
CH1/CH2 (主站) → 智能排队引擎 → CH3 (从机总线)
     ↓              状态机驱动         ↓
  请求接收         优先级排序      单线程发送
  地址验证         超时管理        响应路由
```

#### ⚡ 性能特性
- **零拷贝缓冲池**: 8个1KB预分配缓冲区，避免内存拷贝
- **状态机设计**: IDLE/WAITING两状态，避免重复发送
- **优先级排序**: 基于剩余时间的插入排序算法
- **看门狗保护**: 2倍超时强制重置，防止死锁

#### 📊 关键指标
| 指标项 | 数值 | 说明 |
|--------|------|------|
| **请求延迟** | < 15ms | 主循环周期 |
| **队列深度** | 8请求 | 可配置 |
| **内存占用** | ~16KB | 缓冲池+队列 |
| **吞吐量** | 50-100 req/s | 取决于从机响应时间 |

#### 🔧 工作流程
```c
1. IDLE状态：
   ├─ 收到CH1/CH2请求 → 直接发送到CH3
   ├─ 发送成功 → 状态变为WAITING (不加入队列)
   └─ 记录源通道 → 用于响应路由

2. WAITING状态：
   ├─ 收到CH1/CH2新请求 → 加入队列 → 按剩余时间排序
   ├─ 收到CH3响应 → 转发到源通道 → 状态变为IDLE
   ├─ 超时检查 → 移除超时请求 → 状态变为IDLE
   └─ 看门狗触发 → 强制重置 → 状态变为IDLE

3. IDLE状态且队列非空：
   ├─ 取队列首部请求(剩余时间最短)
   ├─ 发送到CH3
   └─ 状态变为WAITING
```

#### ✨ 重要优化
- **禁用抛弃机制**: 避免刚发送就被抛弃导致重复发送
- **直接发送不入队**: IDLE时直接发送，避免重复发送
- **精确状态管理**: `current_waiting_index = -1` 表示不在队列中
- **源通道记录**: `current_source_channel` 确保响应正确路由

### 2. 📊 Modbus-RTU轮询缓存模式 (Modbus-RTU Polling Cache Mode)

**企业级Modbus设备管理系统**，支持自动和手动两种缓存模式。

#### 核心特性
- **自动智能缓存**: 动态发现设备，自动建立缓存
- **手动精确配置**: 精确控制轮询设备和地址范围
- **写后验证**: 写操作完成后自动读取验证
- **高速轮询**: 100ms间隔，支持大量设备同时监控

#### 缓存机制
```c
读请求处理：
1. 查找缓存 → 命中率 > 95%
2. 直接返回缓存数据 → 延迟 < 5ms
3. 后台轮询维护缓存新鲜度

写请求处理：
1. 暂停轮询 → 避免冲突
2. 发送写命令到从机
3. 等待写响应
4. 读取验证 → 更新缓存
5. 恢复轮询
```

#### 失败管理
- **连续失败计数**: 3次失败自动删除缓存条目
- **智能重试**: CRC错误、超时、异常响应分别处理
- **垃圾回收**: 60秒定期清理失效缓存

### 3. 🎯 Modbus过滤透传排队模式 (Modbus Filter Transparent Queue Mode)

**基于 transparent_queue 重写的高性能Modbus网关**，完美融合地址过滤、虚拟映射与智能排队。

#### 🚀 架构革新

**完全重写的排队引擎**：
```
原架构（已弃用）          新架构（当前版本）
├─ 复杂的多路径逻辑      →  统一的状态机设计
├─ 多个状态变量          →  单一状态机驱动
├─ 非队列模式直接发送    →  IDLE直接发送+源通道记录
└─ 响应路由混乱          →  精确的响应路由

代码行数：~2000行 → ~1000行（精简50%）
可维护性：低 → 高
可靠性：中 → 极高
```

#### 🎨 核心功能

**1. 智能地址过滤系统**
```c
白名单模式（WHITELIST）：
├─ 起始地址必须在配置范围内
├─ 结束地址必须在配置范围内
└─ 两条件同时满足才允许通过

黑名单模式（BLACKLIST）：
├─ 检查地址范围是否与禁止范围重叠
├─ 使用区间重叠算法: req_start <= cfg_end && req_end >= cfg_start
└─ 任何重叠都拒绝
```

**配置示例**：
```
白名单：从机1，地址100-200
├─ 请求150-160 → ✅ 通过（完全在范围内）
├─ 请求90-110  → ❌ 拒绝（起始地址不在范围）
└─ 请求190-210 → ❌ 拒绝（结束地址不在范围）

黑名单：从机1，禁止100-200
├─ 请求50-90   → ✅ 通过（无重叠）
├─ 请求90-110  → ❌ 拒绝（有重叠）
└─ 请求250-260 → ✅ 通过（无重叠）
```

**2. 从机地址映射**
```c
虚拟化功能：
├─ 虚拟地址 → 真实地址 (请求包处理)
├─ 真实地址 → 虚拟地址 (响应包处理)
├─ CRC自动重算 (地址变化后)
└─ 防直接访问真实地址 (安全隔离)

缓存加速：
├─ 哈希表查找: O(1)平均时间
├─ 线性探测解决冲突
├─ TTL机制: 1秒缓存生存时间
└─ 32条目环形缓存
```

**3. 统一排队逻辑**
```c
完全继承 transparent_queue 的排队算法：
├─ 零拷贝缓冲池管理
├─ IDLE/WAITING状态机
├─ 基于剩余时间的优先级排序
├─ 看门狗超时保护
└─ 精确的响应路由机制

在此基础上增加：
├─ 地址过滤检查 (在入队前)
├─ 地址映射处理 (虚拟→真实)
└─ 响应映射处理 (真实→虚拟)
```

### 4. 🔗 一主多从模式 (Master-Slave Mode)

**高效的数据转发机制**，实现一个主站总线与多个从站总线的双向透明转发。

#### 核心架构
```
CH1 (主站总线) ←→ ESP32-S3集线器 ←→ CH2, CH3 (从站总线)
      UART1                              UART0, UART2
    GPIO15/7/2                       GPIO43/44/4, GPIO17/16/5
```

#### 转发规则
1. **主站→从站**: CH1数据同时转发到CH2和CH3
2. **从站→主站**: CH2和CH3数据都转发到CH1  
3. **数据隔离**: CH2和CH3之间不直接通信

#### 性能指标
- **延迟**: < 20ms (数据接收到转发)
- **吞吐量**: 支持115200bps传输速率
- **并发性**: 三通道独立处理
- **稳定性**: 7×24小时连续运行

### 🔄 多任务冲突防护机制

**智能工作模式互斥系统**，确保同一时间只有一个工作模式任务运行。

#### 问题背景
在模式切换时，如果旧模式任务未正确退出，可能导致：
- ✗ 多个任务同时向CH3发送请求（重复发送）
- ✗ 响应路由到错误的通道
- ✗ 数据包混乱和CRC校验失败

#### 解决方案
```c
// 每个工作模式任务启动时的检查机制
void transparent_task(void *pvParameter) {
    char work_mode[32] = {0};
    nvs_handle_t nvs_check;
    
    if (nvs_open("storage", NVS_READONLY, &nvs_check) == ESP_OK) {
        nvs_get_str(nvs_check, "w_mode", work_mode, &len);
        nvs_close(nvs_check);
        
        if (strcmp(work_mode, "transparent_queue") != 0) {
            ESP_LOGW(TAG, "当前工作模式不是transparent_queue，任务退出");
            vTaskDelete(NULL);  // 立即终止自己
            return;
        }
    }
    
    // 正常任务逻辑...
}
```

✅ `sx_transparent_queue.c` - 排队透传模式  
✅ `sx_modbus_queue.c` - Modbus过滤排队模式

#### 2. 状态机设计
```c
typedef enum {
    QUEUE_IDLE = 0,      // 空闲状态：可以直接发送
    QUEUE_WAITING        // 等待状态：等待CH3响应

// 全局状态变量
```

#### 3. 智能优先级排序
```c
// 基于剩余时间的插入排序 - O(n) 时间复杂度
static void sort_queue_by_remaining_time(void) {
    for (int i = 1; i < queue_size; i++) {
        queue_request_t key = request_queue[i];
        int j = i - 1;
        
        while (j >= 0 && request_queue[j].remaining_time_ms > key.remaining_time_ms) {
            request_queue[j + 1] = request_queue[j];
            j--;
        }
        request_queue[j + 1] = key;
    }
}
```
