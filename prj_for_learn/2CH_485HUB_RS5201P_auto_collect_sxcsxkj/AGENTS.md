# 项目协作约定

## Git 提交

- 用户要求 `commit` 时，必须检查完整的 `git status`，并提交项目中的全部变更。
- 不得因为文件位于 `build/`、属于生成文件、被 `.gitignore` 忽略或文件数量较多而擅自遗漏。
- 提交前应使用覆盖完整工作区的暂存方式；属于项目内容但被忽略的文件，必须按需使用强制暂存纳入提交，并确认关键的未跟踪、删除和修改状态都已处理。
- 提交后必须再次检查 `git status`，避免留下未说明的项目文件变更。

## 按提交恢复项目

- 用户要求回到某次提交时，目标是让项目目录与该提交完全一致，而不是只恢复源代码。
- 应恢复该提交中的全部已跟踪文件，包括 `build/` 和其他生成文件。
- 对于目标提交之外的未跟踪文件、被忽略文件和目录，只有在用户明确要求完整回退时，才清理它们，避免残留文件造成项目状态混乱。
- 执行完整回退前必须先确认目标提交，并检查当前工作区；回退操作可能永久删除当前未提交的文件。
