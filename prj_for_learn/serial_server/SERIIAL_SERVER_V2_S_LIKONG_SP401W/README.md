# 串口服务器 V2 项目

## 项目概述

这是一个基于ESP32的串口服务器项目，支持多种工作模式，包括MQTT/TCP透传、Modbus-TCP转Modbus-RTU以及Modbus-RTU网关模式。

## 最新更新：轮询间隔时间优化

### 功能描述

在Modbus-RTU网关模式下，轮询间隔时间单位已从毫秒改为秒，提供更直观的用户体验和更智能的验证机制。

### 主要改进

1. **单位变更**：轮询间隔时间从毫秒改为秒
   - 界面显示：30秒（而非30000毫秒）
   - 默认值：30秒
   - 输入范围：1秒 ~ 3600秒（1小时）

2. **智能验证**：自动验证轮询间隔时间的合理性
   - 确保轮询间隔时间大于所有启用模板的（接收超时时间 + 间隔时间）
   - 如果设置值过小，系统会自动调整并提示用户
   - 防止因时间设置不当导致的通信异常

3. **用户体验提升**：
   - 设置时显示友好的确认对话框
   - 清晰说明最小时间要求的计算方式
   - 自动调整建议值

### 使用方法

#### 基本设置
1. 选择"Modbus-RTU网关"工作模式
2. 在"轮询间隔时间"字段输入秒数（如：30）
3. 配置Modbus模板的接收超时时间和间隔时间
4. 点击"设置"按钮

#### 验证逻辑
系统会自动计算所有启用模板的最大（接收超时时间 + 间隔时间），并要求：
```
轮询间隔时间 ≥ max(模板接收超时时间 + 模板间隔时间) + 1秒缓冲
```

#### 示例场景
```
模板1：接收超时 1000ms + 间隔时间 500ms = 1500ms
模板2：接收超时 2000ms + 间隔时间 800ms = 2800ms
模板3：接收超时 1500ms + 间隔时间 300ms = 1800ms

最大模板时间 = 2800ms
最小轮询间隔时间 = 2800ms + 1000ms = 3800ms ≈ 4秒
```

如果用户设置轮询间隔时间为3秒，系统会提示调整为4秒。

### 注意事项

1. **最小值限制**：轮询间隔时间不能小于1秒
2. **最大值限制**：轮询间隔时间不能大于3600秒（1小时）
3. **自动调整**：如果设置的时间不满足要求，系统会自动调整并通知用户
4. **实时验证**：每次修改模板配置后，再次设置轮询间隔时间时会重新验证

### 错误处理

- 输入非数字值：提示"轮询间隔时间必须是大于0的整数"
- 时间过小：自动调整为最小安全值
- 时间过大：自动调整为最大允许值
- 网络异常：显示错误提示并保持原设置

## UART 接收聚合优化（2025-10-30）

### 背景

- 现场反馈串口长帧（>256B）被拆分成多段，协议栈解析失败。
- 原有实现使用固定超时与 FIFO 阈值，首次触发就立刻读取，无法保证整帧到齐。

### 关键修改

- `main/sx_async_uart.c`
  - 新增“持续聚合”逻辑：循环查询 UART FIFO 并读取，结合 `calculate_wait_time_ms()` 动态延长等待时间；直到数据稳定或达到缓冲上限后再处理。
  - 写入 `uart_response` 前增加容量保护，仅复制可容纳的数据，并在超长帧时打印日志提示。
  - 对无数据/读满等场景输出调试日志，协助定位硬件或协议问题。
- `main/include/sx_async_uart.h`
  - 引入公共宏 `UART_IO_BUF_SIZE` 并将 `uart_response` 扩容至 4096 字节，统一串口缓冲容量。
- `main/sx_mqtt_client.c`
  - 移除对旧版串口缓冲 extern 的依赖，避免与新定义冲突。

### 效果

- 串口长帧可一次性送达 WebSocket/MQTT/TCP 上层，消除分包现象。
- 日志中“聚合完成”“缓冲区上限”等提示可快速判断帧是否完整。
- 保留 4 KB 缓冲并可按需扩展，满足 Modbus、透传等场景的帧长度需求。

### 接收流程详解

1. **配置阶段**（`uart_init()` → `uart_configure()`）
   - 从 NVS 读取波特率、数据位、校验位、停止位、帧时间、最大帧长等。
   - 设置 UART2 参数、RS485 管脚、RX FIFO 阈值=10、RX 超时（按帧时间换算并限制在 1~101 字符）。
   - 根据 `frame_len` 选择 256~4096 字节的接收缓冲区，并保存当前波特率与每字符位数供后续计算。
   - 重启驱动后调用 `rx_wait()` 创建接收任务。

2. **运行时聚合**（`rx_task()` 主循环）：
   - 轮询 `uart_get_buffered_data_len()` 检查 FIFO；若无数据短暂休眠 10 ms。
   - 若处于 Modbus 模式，会先尝试解析功能码并预测完整长度；其余情况走通用路径。
   - 通用路径分配 4 KB 缓冲后进入循环：
     1. 读取 FIFO 可用字节，按剩余容量读取；
     2. 若读取成功，刷新 `frame_deadline`（基于 `calculate_wait_time_ms()` 动态估算所需传输时间并加安全余量）；
     3. 若连续多次读取不到数据且超过 deadline，认为帧结束；
     4. 若长度达到缓冲上限，打印告警并退出循环。
   - 聚合完成后输出日志“聚合完成，最终长度: xx bytes”，便于现场确认是否收齐。

3. **数据分发**：
   - 在临界区内清空 `uart_response`（4 KB）并复制实际读取字节；若帧超长，仅保留前 4 KB 并日志告警，同时 `response_len` 记录真实字节数。
   - 调用 `send_uart_to_websocket()` 将原始二进制通过 WebSocket 推送前端调试界面。
   - 根据工作模式触发 MQTT 发布、TCP 透传或 Modbus 模板匹配等后续处理。

4. **辅助逻辑**：
   - `calculate_wait_time_ms()` 根据当前波特率和字符位数估算传输时长（并加 50% 裕量，限制 10~2000 ms），既用于通用聚合，也用于 Modbus 智能等待。
   - `sendData()` 在发送前多次 `uart_flush_input()` 清理历史数据，发送后延时 3 ms 以切换 RS485 方向。
   - 日志覆盖“未读取到有效数据”“达到缓冲区上限”等场景，帮助排查线路噪声、波特率不匹配等问题。
