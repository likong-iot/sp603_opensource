# SP603 多串口物联网网关底层固件

本工程提供 SP603 的串口驱动、网络管理、配置存储、状态指示、按键复位和调试等基础能力，供业务固件进行二次开发。当前串口透传功能是使用这些基础能力的示例；自动采集用于底层功能测试。

本文介绍基础固件的功能和设备行为。源码获取、编译烧录、API 调用及新增业务的方法见 [《SP603 二次开发说明》](二次开发说明.md)。

## 基础功能

| 功能 | 说明 |
| --- | --- |
| 串口驱动 | 多串口独立接收任务、按帧间隔收包、按口收发、运行参数配置和数据活动指示 |
| 串口布局 | 双 RS485 + RS232，或 RS422 + RS232；识别 UART0 调试控制台占用 |
| 以太网 | W5500 链路管理、静态 IP / DHCP 客户端、下行 DHCP 服务 |
| Wi-Fi | STA 联网、AP 管理热点、扫描、断线重连和热点定时关闭 |
| 4G | AIR780E USB 接入、PPP 拨号、启动重试及连接状态上报 |
| 网络管理 | 自动选择上行接口、维护默认路由及 DNS、按配置提供下行 NAPT 转发 |
| 配置存储 | NVS 持久化、补齐缺失默认参数、配置读取与校验、重启后加载 |
| 系统操作 | 按键重启、长按恢复出厂、软件重启及恢复出厂入口 |
| 状态和调试 | SYS / 网络 / 串口 LED、系统日志、串口调试、浏览器时间同步 |

当前透传示例支持每口选择 TCP Server、TCP Client、MQTT 或 Modbus TCP/RTU 转换。自动采集是测试用途，不作为通用采集平台说明。当前 OTA 接口未启用，Modbus 过滤和从站映射接口返回不支持。

## 串口与硬件资源

端口参数使用工程内部编号，与面板标号、ESP-IDF 的 `UART_NUM_x` 不完全相同。

| 布局 | 面板接口 | 业务端口编号 | 使用的 UART |
| --- | --- | --- | --- |
| 双 RS485 | COM1 / RS485-1 | `3` | UART0 |
| 双 RS485 | COM2 / RS485-2 | `1` | UART1 |
| 双 RS485 | RS232 | `2` | UART2 |
| RS422 | RS422 | `1` | UART0 发送、UART1 接收 |
| RS422 | RS232 | `2` | UART2 |

RS422 布局会共同使用 COM1、COM2 的硬件资源，不能同时作为两个独立 RS485 口使用。串口布局保存后重启生效。为保持 API 兼容性，RS422 运行时改参仍需分别配置收发两端，具体约定及示例见开发文档 5.5.4。

当前 `sdkconfig` 关闭应用 UART 控制台，UART0 可供业务使用；若改为 UART0 调试控制台，COM1 将被占用，RS422 布局也无法使用。

## 网络与默认访问方式

以下是当前代码在首次启动或恢复出厂后建立的默认配置，已保存的用户参数优先。

| 项目 | 默认行为 |
| --- | --- |
| 以太网 | 启用上行，静态 IP `192.168.1.84`，掩码 `255.255.255.0`，网关 `192.168.1.1` |
| Wi-Fi STA | 关闭，配置 SSID 和密码后启用 |
| Wi-Fi AP | 启用本地管理热点，默认名称 `SP603_XXXX`，`XXXX` 为 STA MAC 地址末两字节的十六进制表示 |
| AP 密码 / 地址 | `12345678` / `192.168.4.1`，向连接设备提供 DHCP |
| AP 开放时间 | 默认 30 分钟，到时自动关闭；具体以保存的热点开放时间配置为准 |
| 4G | 启用上行，连接成功需满足模组、SIM 卡和运营商网络条件 |
| 管理页面 | HTTP 端口 `80`；默认账号 `admin`，密码 `12345678` |
| 默认串口布局 / 参数 | 双 RS485；9600、8 数据位、无校验、1 停止位 |
| 默认示例 | `serial_server` 串口服务器 |

首次连接可使用同网段以太网访问 `http://192.168.1.84`，或连接管理热点后访问 `http://192.168.4.1`。热点已超时关闭时，可以重启设备重新启动已启用的热点。

可用上行接口按 **以太网 → 4G → Wi-Fi STA** 的顺序自动选择，选择依据包括接口启用、角色及获得 IP 的状态。当前接口失去可用状态时重新选择。互联网探测用于网络状态指示，不能据此认为所有业务连接都会自动恢复；透传示例分别处理自己的连接。

AP 可作为本地管理网络或下行网络，以太网也可配置为下行网络。当前路由设计一次支持一个下行 NAPT 接口。网络参数保存后需要重启，管理热点与上行接口的作用应按实际配置区分。

以太网上行通过静态地址开关选择静态 IP 或 DHCP 客户端；以太网的 DHCP 服务开关仅用于下行地址分配。下行始终使用配置的静态地址，开启 DHCP 服务后在网线接通时启动、断开时停止，向客户端提供本机下行地址作为网关，以及配置的有效 DNS。下行关闭 DHCP 时，客户端需自行配置静态地址。参数和验证方法见开发文档 5.5.6、5.8.5。

## 配置保存与生效

配置保存在 NVS Flash 中，主要公共命名空间为 `storage`。启动时补齐缺失的默认参数，正常情况下不覆盖已保存的用户值。

| 操作 | 行为 |
| --- | --- |
| 普通断电 / 重启 | 保留已提交到 NVS 的配置，启动时重新读取 |
| 网络配置保存 | 保存参数并标记需要重启，重启后按新参数启动网络 |
| 串口布局保存 | 保存布局，重启生效 |
| 串口运行时改参 | 修改当前 UART 参数；直接调用驱动配置 API 不会自动写 NVS |
| 透传示例配置保存 | 保存各口的协议和串口参数；运行参数应用与持久化是不同步骤 |
| 恢复出厂 | 擦除默认 NVS 分区并重启，下次启动重建默认配置 |

恢复出厂会清除该 NVS 分区内的用户参数，包括放在自定义命名空间中的业务配置；不会通过此操作重新烧录应用固件。NVS 初始化检测到无可用页或版本不兼容时，当前启动代码也会擦除并重新初始化 NVS。

## 按键、重启与恢复出厂

面板按键低电平有效，按 10 ms 周期扫描并消抖。

| 操作 | 设备行为 | 配置是否保留 |
| --- | --- | --- |
| 短按后松开 | 有效按住约 50 ms 至不足 1 秒，执行软件重启 | 保留 |
| 持续按住约 5 秒 | 自动触发恢复出厂，启动指示、停止业务和串口接收，等待指示后擦除 NVS、重启 | 清除 |
| 管理页面重启 | 返回响应并给出重启指示后重启 | 保留 |
| 管理页面恢复出厂 | 返回响应并给出恢复出厂指示后擦除 NVS、重启 | 清除 |

以上按住时间为消抖确认后的计时，实际操作需留出消抖余量。按住 1 秒以上但不足恢复出厂门限再松开，不执行短按重启。恢复出厂指示是所有面板灯按约 0.5 秒亮、0.5 秒灭闪烁三次；重启指示请求一次闪烁后设备重启。

## 指示灯状态

面板 LED 经 ULN2003 驱动，GPIO 高电平点亮、低电平熄灭。系统操作指示期间会临时覆盖普通灯效。

### 网络指示灯

LAN 对应 W5500，WIFI 对应 Wi-Fi STA/AP，4G 对应 AIR780E。三者采用以下统一节奏，状态由网络管理器设置。

| 灯效 | 含义 |
| --- | --- |
| 熄灭 | 接口未启用 |
| 每秒三次短闪 | 接口已启用，连接中、等待探测，或当前未被选为活动上行 |
| 每秒两次短闪 | 活动上行探测为仅本地可达，或 Wi-Fi AP 作为本地管理网络 |
| 1 秒亮、1 秒灭 | 正在提供下行网络服务 |
| 常亮 | 当前活动上行通过互联网可达性探测 |

短闪每次约 100 ms。备用接口即使已获得 IP，也不一定常亮；活动上行失去互联网探测响应时会显示本地状态。Wi-Fi STA 和 AP 共用一个 WIFI 灯，STA 为当前活动上行时优先显示该上行状态。此表对应当前 `sx_network_manager.c` 和 `sx_led_manager.c` 的实现。

### SYS 系统运行灯

SYS 表示系统运行状态。

| 状态 | 灯效 | 说明 |
| --- | --- | --- |
| 启动中 | 200 ms 亮、200 ms 灭 | 基础组件及应用尚未完成启动 |
| 正常运行 | 500 ms 亮、500 ms 灭 | 应用已就绪，未满足系统警告条件 |
| 警告 | 200 ms 亮、1.8 秒灭 | 配置接口启动失败，或需要上行但无活动接口 / 可用 DNS |
| 严重错误 | 125 ms 亮、125 ms 灭 | 主流程检测到严重初始化错误时请求此状态；若随后发生系统复位，灯效可能短暂 |

### 串口数据灯

COM1、COM2、RS232 三个灯表示对应串口的数据活动，活动后保持约 100 ms。发送灯在驱动成功写入后点亮，并覆盖等待发送完成的过程。

- 双 RS485 布局：COM1、COM2、RS232 分别对应各自接口，收发共用数据灯。
- RS422 布局：COM1 表示 RS422 发送，COM2 表示 RS422 接收，RS232 保持独立。

## 日志、时间与透传示例

固件提供系统日志缓存、ESP 日志捕获和串口调试数据展示。系统日志捕获默认关闭，可在管理页面启用；日志主要存于 RAM，重启后不保留。当前应用 UART 控制台关闭，查看应用日志优先使用管理页面。

时间通过浏览器同步后用于应用时间戳；未同步时以启动以来的计时为基础。当前时间管理模块不提供独立 NTP 或掉电 RTC 保时。

透传示例位于 `main/sx_serial_server.c`，展示如何组合串口、网络、配置和日志能力：

- 串口数据通过工作模式处理入口进入 TCP / MQTT 等发送逻辑。
- 网络数据调用 `async_uart` 的发送接口返回对应串口。
- 各口协议、参数和运行状态分别管理。

开发者可据此编写自己的工作模式，自动采集仅作底层测试参考。当前实现已补齐模式启停失败处理、1.5 停止位兼容及 RS422 可用口校验；TCP / MQTT 发送采用有界队列，拥塞或错误时断开重建。网络配置保存后重启生效，运行状态与待重启配置分开显示。发送边界、故障回归命令和实机验收要求详见 [《SP603 二次开发说明》](二次开发说明.md) 5.8.5、5.8.7；API 和接入示例以该文档及当前头文件为准。
